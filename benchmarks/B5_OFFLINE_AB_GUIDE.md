# b5のBVE不要オフライン自動検証

## 導入した目的

BVE本体を毎回起動して240秒運転しなければコード改良が検証できない状態を減らすため、非公開b5開発ブランチに模擬ATSの自動回帰試験と、改良前後のA/B比較を追加した。

今回の比較対象：
- 旧b5フロントエンド：診断ログを300フレームごとに開いて直接書き込む実装
- 改良後b5フロントエンド：診断ログを4096行の上限付きメモリに蓄積してDispose時に一括書き込む実装
- 同じx86バックエンド、同じモックATS、同じx64運転ハーネスを各試行で使用
- ATS往復のパネル高番号255・音声負数・ハンドル状態の一致を各フレームで検証

## 自動化の内容

- CompareB5BufferedDiagnostics.pyは旧DLLと新DLLを交互に起動し、一定フレーム数の模擬ATS通信を実行する。
- 各試行は独立ディレクトリにDLL、バックエンド、模擬ATS、bridge.logを分離する。
- スクリプトは応答失敗やフレーム数不一致、9段階の計測不一致、診断行欠落、バッファ超過、同じDLLを比較しようとする操作をエラーとして扱う。
- CSVとMarkdownに、ステージ別処理時間、全フレーム往復平均、試行時間、SHA256、計測上の制約をまとめる。
- RunB5OfflineChecks.ps1はC++/C#をビルドし、模擬ATSハーネスをビルドし、Pythonの単体テスト5種類を実行した後、旧版との比較を実行する。
- スクリプトはBveTs.exeや路線・車両データを開かず、Windowsの管理者権限やPresentMonも使用しない。
- 出力先は通常dist-b5/offline-checks以下の時刻付きフォルダー。既存の記録は上書きしない。
- 旧DLLの基準SHA256はDC993F0790AE11D7A58AC5C5BC739E1C4F85E56728F6A19A9133D324AEAFD42B。ローカルではdist-b5/benchmark-baseline/frontend-prebuffer.dllとして保持している。Gitや共有用ZIPには含めない。
- Windows PC以外、Visual Studio MSBuildやPythonがない環境では自動実行できない。

## 2026年11月1日のA/B実測（模擬ATS）

設定：1回につき12000フレーム、旧版3回・新版3回、順序を交互にして実行。

| 指標（3試行の中央値） | 旧b5 | 改良後b5 |
|---|---:|---:|
| frame_log平均 | 1.048μs | 0.250μs |
| frame_log最大 | 393.6μs | 36.5μs |
| ブリッジfull平均 | 216.518μs | 213.728μs |
| 1回のテスト実行時間 | 3.218秒 | 3.323秒 |

試行は全6回とも成功し、ATSの状態値、フレーム数、定期診断の行数が保持された。frame_logの平均処理時間は模擬環境で減ったが、1回のテスト全体の実行時間はほぼ同等であり、BVE実走行FPSの向上を証明するものではない。Windowsの一時停止、GPU描画や運転画面のフレーム間隔はこの試験では計測しない。

## 今後の運用

- コード変更ごとにこのオフラインテストを開発作業内で実行し、BVEの手動起動を要求しない。
- 新規テストでATS互換の誤りや実行失敗が出た場合、次の実車両テストへ進まない。
- 多数の小変更ごとにBVEの運転テストを依頼する運用はやめ、BVE実走行が必要な機能をひとまとまりにした段階で確認を行う。
- ただし、最終的なFPS改善やカクつき解消はゲーム本体での再現性がある確認が必要。オフラインで性能改善が確定したとは記述しない。

## 開発者用実行例

PowerShellで以下を実行する。旧DLLと模擬ATSがローカルに配置されていることが必要。

powershell.exe -NoProfile -ExecutionPolicy Bypass -File benchmarks/RunB5OfflineChecks.ps1

デフォルトでは12000フレームを旧版・新版それぞれ3回ずつ実行する。各実行の結果は新しいフォルダーに保存する。
## 60Hz・30Hz相当の周期検証

模擬ATSとの通信を16,667μsと33,333μsの周期で呼び出し、ATS本体85msの一時停止とハーネス側120msの一時停止が正しい段階に記録されることを検証する。既定のオフライン一括テストへ追加済み。詳しくはB5_CADENCE_STALL_GUIDE.md。
