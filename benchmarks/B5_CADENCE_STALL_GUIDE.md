# b5 オフライン周期・ATS一時停止回帰テスト

## 目的

毎回BVE6を起動して240秒運転する操作を減らし、実際の運転で観測した
描画系列A（約31提出/秒）と系列B（約64提出/秒）に近い呼び出し周期で、
ATSブリッジの模擬通信・遅延の記録を確認できるようにした。

本テストはx64模擬運転ハーネス、32ビットATS模擬プラグインと
BVE6用互換ブリッジのみを利用する。BveTs.exeや車両・路線データ、
GPU描画、PresentMonは使わず、実際のBVE FPSは測定しない。

## 追加した機能

- 模擬ATSハーネスを任意の周期（既定16,667μs＝約60Hz相当）で呼び出せるようにした。
- 32ビットATS本体に設定した一時停止（既定frame 450で85ms）を追加可能にした。
- 模擬運転側でも別のフレーム（既定frame 400で120ms）の入力間隔を作れるようにした。
- もともと存在したframe 123で25msのATS側停止は維持した。
- フレームごとにブレーキ、力行、パネルの端の要素、音声状態が一致することを確認する。
- 85msのATS側停止はhost ATS段階とfrontend receive段階へ現れること、
  120msのハーネス側停止は次フレームのhost stdin入力待ちに現れることを検証する。
- 改良後のフロントエンドでは、運転中の診断ログがbridge.logに直接出力されないことを確認する。
- RunB5CadenceRegression.pyが旧版・改良版を独立プロセスで実行し、CSVとMarkdownに検証結果を保存する。
- RunB5OfflineChecks.ps1が従来のC++/C#ビルド・模擬ATS A/B試験に加え、
  約60Hz（16,667μs）と約30Hz（33,333μs）の2条件を既定で自動実行する。
- 単体テストtest_b5_cadence.pyは、ATS実処理と入力待ちを混同しないことや
  実FPSを計測したと誤記しないレポートを確認する。

## 2026年11月1日 実施結果（模擬実行のみ）

約60Hz相当、各600回のATS呼び出し：

| 項目 | 旧版 | 改良版 |
|---|---:|---:|
| 全往復通信 | 600件成功 | 600件成功 |
| ATS一時停止の実測 | 94.09ms | 94.55ms |
| host stdin入力待ち | 137.48ms | 154.22ms |
| frontend frame_log平均 | 1.587μs | 0.448μs |
| frontend frame_log最大 | 241.50μs | 19.80μs |

約30Hz相当、各600回のATS呼び出し：

| 項目 | 旧版 | 改良版 |
|---|---:|---:|
| 全往復通信 | 600件成功 | 600件成功 |
| ATS一時停止の実測 | 91.55ms | 94.24ms |
| host stdin入力待ち | 171.31ms | 154.51ms |
| frontend frame_log平均 | 672.596μs | 0.454μs |
| frontend frame_log最大 | 402833.4μs | 24.9μs |

約30Hz試験で旧版に約403msの長いログ処理が記録された。
ただし旧版のファイルopen/write自体が停止したのか、Windows側の
スケジューリングが重なったのかはこれだけでは断定できない。
同じ模擬条件で改良版には同規模の停止が記録されなかったが、
1回のA/B試験だけで実際の運転でのFPS改善を保証できない。

## 30Hz条件の再実行での確認

同一日にオフライン一括テストを再実行したところ、30Hz条件での
frame_log最大値は旧版292.6μs、新版18.8μsだった。
初回試行で記録された旧版402833.4μs（約403ms）は、この再実行では
再現しなかった。実行時のWindowsスケジューリングやファイルアクセスの
状態によるばらつきが存在するため、単発の最大値を必然的な挙動とみなさない。

いずれの試験でも、ATS一時停止と入力待ちを別々に検出し、
通信フレームの状態値は一致した。実BVEのFPSを計測したわけではない。
## 自動テスト実行

ローカル開発PCでPowerShellから以下を実行：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File benchmarks/RunB5OfflineChecks.ps1

既定で（1）x86/x64ビルド、（2）Pythonの回帰試験、
（3）バースト処理A/Bを旧・新それぞれ3回、
（4）約60Hz・約30Hzの2条件でATS一時停止を再現する模擬テストを実行する。

すばやく模擬通信のみを確認する場合は -SkipPacedRegression を付けられる。
既存のテスト記録は上書きせず新しい出力フォルダーに保存される。
オフライン検証が失敗したら実走行の検証には進まない。

## 制限

- 実路線、実ATS、BVE6の描画スレッド、GPUの負荷を再現できない。
- 模擬ATSの一時停止やWindowsスケジューラは実際の運転とは異なる。
- 本試験のframe_log改善を実FPSの改善率に換算してはならない。
- 公開済みb4は変更していない。今回の追加は非公開b5開発版のみ。
