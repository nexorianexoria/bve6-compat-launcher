# b5：自動FPS/ATS解析と配列変換の性能比較

## 変更内容

- CaptureB5Timing.ps1 に AnalyzeAfterExit スイッチを追加。これを指定すると、QPC付きのFPS記録完了後にBVEの通常終了を待ち、ATSログが確定してから解析する（自動終了は行わない）。
- AnalyzeB5Run.ps1 を追加。FPSのCSV・capture-metadata.txtからBVEのPIDを読み、ランチャーが出力した同じPID・同じ時間帯の実行ログを探して、bridge.logを特定する。
- 対応する実行ログが複数またはゼロ、BVEがまだ終了していない、CSV内のProcessIDがcapture-metadataと一致しない、bridge.logに必要な集計がない場合は解析を中止する。
- BVEの実行終了が未確認の場合はログを勝手に読まない。WaitForExitを指定した場合もBVEを強制終了せず、通常終了を待つ。
- Windows PowerShell 5.1向けにAnalyzeB5Run.ps1をUTF-8 BOMで保存。ランチャーログはUTF-8として明示的に読む。
- AnalyzeB5Goal.py と CorrelateBveStalls.py は、5ms超のATS処理が0件だった実行も、集計ログが正常に存在する場合に限り、正常なレポートとして扱う。イベント自体のない不完全なログは拒否する。

### 次回以降の計測

BVE6を開いてから、管理者PowerShellで新しい開発版のフォルダーに移動し、以下を実行する。

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\benchmarks\CaptureB5Timing.ps1" -AnalyzeAfterExit

収録は最大240秒で、BVEを先に終了した場合は記録を停止する。240秒の記録後も、BVEを通常終了すると解析レポートを出力する。既存のFPS CSVのみを解析する場合：

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\benchmarks\AnalyzeB5Run.ps1"

既定では最新のCSVを使用する。別のフォルダーのデータを使う場合は -CsvPath と -LauncherDataDirectory を明示する。メタデータ等が不一致の場合は自動で選ばずエラーを表示する。出力ファイルは既存ファイルを上書きしない。

## 配列の16進変換：試験結果

フロントエンドとホストが共有する256個のint値を16進文字列へ変換・復元する処理について、符号化をビットシフトへ、復号をルックアップ表へ変更して模擬ATSによる性能比較を実施。基準は未使用パネル比較の削除が済んだb5であり、各条件20,000フレーム×5回の集計を比較。

| 処理 | 元の実装の平均 | 試験版の平均 |
|---|---:|---:|
| ブリッジ全体（core） | 244.14µs | 262.23µs |
| フロントエンド符号化（encode） | 16.83µs | 18.66µs |
| フロントエンド復号（decode） | 50.38µs | 53.74µs |
| ホスト受信解析（parse） | 45.24µs | 46.45µs |
| ホスト符号化（encode） | 15.09µs | 13.03µs |

**全体として高速化が確認できず、この配列変換の変更は取り消した。** 元のencoder.hに復元し、C++のx64・x86バイナリを再ビルド。模擬ATSで3,000回の往復テストが成功している。

これらは合成ATSによる試験値であり、FPSや実際のATSの処理時間を表すものではない。順番を交互にした無作為な比較でもないため、環境差の影響が残る。

## 検証内容

- 過去の240秒の実走行CSV・ランチャーログ・bridge.logの組み合わせを自動で選べることを確認。58件のホストATS遅延イベントを解析。
- コピーしたテスト環境の日本語作業データフォルダーを自動的に扱い、UTF-8のランチャーログを読み込めることを確認。
- 意図的に異なるPIDを持たせたメタデータは拒否してレポートを作成しなかった。
- 5ms以上の遅延イベントが0件のケース、および必要なログが存在しないケースをテスト。
- C++バイナリは不採用の試験コードを含まないよう再ビルド済み。

実際の運転画面と描画系列はまだ確定していない。ATSとの時間的関連が示されても原因は未確定である。FPS改善が実証されたと主張しない。
